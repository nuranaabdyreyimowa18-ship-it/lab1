# Отчёт о качестве данных (Quality Report)

## 1. Введение
Данный отчёт посвящён первичному исследованию исторического датасета продаж розничной сети супермаркетов, охватывающего транзакции в трёх филиалах за трёхмесячный период. Актуальность анализа обусловлена необходимостью глубокого понимания структуры продаж для последующего моделирования покупательского поведения.

Условным заказчиком анализа выступает топ-менеджмент и аналитический отдел торговой сети. На основе данных могут быть решены такие задачи ИАД, как профилирование групп покупателей (члены клуба vs обычные клиенты), анализ временных паттернов потребительской активности и поиск скрытых аномалий в чеках.

## 2. Паспорт датасета
* **Размерность:** 1000 строк, 17 столбцов (в итоговой полной версии).
* **Ключевые признаки:**
  * `Invoice ID` — уникальный идентификатор транзакции (строковый).
  * `Branch` / `City` — филиал и город продажи (категориальные).
  * `Customer type` / `Gender` — тип клиента и пол (категориальные).
  * `Product line` — товарная группа (категориальный).
  * `Total` — итоговая сумма чека (числовой).
  * `Date` / `Time` — дата и время покупки (временные признаки).
  * `Rating` — оценка покупателя (числовой).

## 3. Основные проблемы качества данных
В ходе аудита исходного файла были зафиксированы следующие особенности:

| № | Тип проблемы | Описание | Потенциальный риск для анализа | Стратегия решения |
|---|---|---|---|---|
| 1 | Неверный тип (Даты) | Колонки Date и Time считались как обычный текст (object) | Невозможность строить графики по времени и анализировать тренды | Приведение типов через `pd.to_datetime()` |
| 2 | Неверный тип (Категории) | Текстовые признаки Branch, Gender, Product line распознаны как общие строки | Избыточное потребление памяти, медленная фильтрация | Преобразование типов в `astype('category')` |
| 3 | Наличие выбросов | В признаке `Total` (Сумма чека) метод IQR зафиксировал значения выше правого уса | Искажение средних показателей при обучении будущих моделей | Сохранить для анализа аномалий, но ограничить при построении линейных моделей |
| 4 | Пропуски данных | Отсутствуют (0 пропущенных значений во всех критических колонках) | Риски отсутствуют | Коррекция не требуется |
| 5 | Дубликаты строк | Полные дубликаты в таблице не обнаружены (0 дубликатов) | Риски отсутствуют | Коррекция не требуется |

## 4. План улучшения качества данных
1. **Этап очистки и восстановления (Высокий приоритет):** Окончательное закрепление типов данных даты/времени и категорий в пайплайне предобработки.
2. **Этап генерации признаков (Средний приоритет):** Извлечение новых признаков из даты (например, `День недели`, `Выходной/Будень`, `Час покупки`) для расширения возможностей анализа.
3. **Этап обработки аномалий (Низкий приоритет):** Исследование природы крупных чеков (выбросов), чтобы исключить вероятность технических сбоев кассового ПО.

## 5. Краткое резюме
В рамках данной лабораторной работы были освоены базовые методы разведочного анализа данных (EDA) с помощью библиотеки Pandas и средств визуализации Seaborn/Matplotlib. Исходный датасет обладает высоким качеством (нет пропусков и дубликатов), однако требует обязательного предварительного преобразования типов данных. Особое внимание при дальнейшем исследовании следует уделить анализу распределения чеков во времени и изучению структуры выбросов.
